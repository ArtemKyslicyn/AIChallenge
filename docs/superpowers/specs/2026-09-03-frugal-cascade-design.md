# FrugalGPT Cascade — Design Spec

**Дата:** 2026-09-03
**Статус:** ready to implement (выбран как Phase D.A мастер-плана)
**Опирается на:** `run_traces` (P1) и `message_feedback` (P2) — уже в проде
**Источник идеи:** [Chen, Zaharia, Zou. FrugalGPT, 2023](https://arxiv.org/abs/2305.05176)

## Зачем это продукту

Сейчас цепочка выбирает модель **до** того, как увидела ответ, и оценивает её постфактум —
по агрегатам (Рейтинг) и по 👍/👎 (Оценки). Каскад добавляет недостающее звено: решение
принимается **по конкретному ответу на конкретный вопрос**. Дешёвая модель отвечает первой,
скорер смотрит на её ответ, и только если ответ не годится — запрос уходит на сильную модель.

Продуктовый эффект, который видно в UI: на «привет» и «переформулируй» тратится дешёвая модель,
а на «спроектируй архитектуру» — сильная, и в футере ответа честно написано, что была эскалация.

## Non-goals

- Никакого обучения скорера (DistilBERT из статьи) на этом хосте
- Не меняем правило «переключение модели только до первого токена»
- Не трогаем soft-penalty из P2 — каскад ортогонален и стакается с ним
- Не кэшируем ответы (это Tier B, отдельная тема)
- Никакого каскада в режимах ×2/×4 — там пользователь сам сравнивает модели

## Главное ограничение: продукт стримит

Каскад требует **увидеть ответ целиком**, прежде чем решать. Стрим требует показать первый
токен как можно раньше. Эти два требования несовместимы в одном проходе, и выбор здесь —
центральное решение спеки.

**Решение: cheap-этап выполняется не-стримом (`complete_chat`), а принятый ответ отдаётся
одним `token`-фреймом.**

- Эскалация происходит до того, как читатель увидел хоть один символ, — то есть правило
  «только до первого токена» соблюдается буквально, а не «почти».
- Уже есть прецедент такого фрейма: `replay_message` отдаёт сохранённый ответ одним куском.
- Честная цена: на cheap-пути пропадает эффект печатающегося текста. Дешёвая модель отвечает
  за ~1–2 с, поэтому это ожидание, а не зависание, но врать анимацией «как будто стрим» нельзя.
- Отвергнутая альтернатива — стримить дешёвую модель и оценивать постфактум: ответ уже
  показан, эскалировать поздно, а стирать показанный текст — худшее, что можно сделать с чатом.

## Скорер

Порт в домене, чтобы реализацию можно было заменить, не трогая use case:

```text
AnswerScorer.score(question: str, answer: str) -> ScoreVerdict
ScoreVerdict = {score: float 0..1, accepted: bool, reason: str}
```

**v1 — эвристический, без единого LLM-вызова.** Это сознательно: LLM-скорер на каждый ответ
съедает ровно ту экономию, ради которой всё затевается.

Отклоняем ответ, если он:

| Признак | Почему это «не годится» |
|---------|--------------------------|
| пустой или короче `CASCADE_MIN_ANSWER_CHARS` | нечего показывать |
| явный отказ («не могу», «как языковая модель», «I cannot») | отказ дешёвой модели — типовой случай для эскалации |
| обрывается на полуслове (нет терминальной пунктуации, не список, не код) | ответ не дописан |
| незакрытый ``` блок кода | сломается рендер markdown |
| язык ответа не совпадает с языком вопроса (кириллица vs латиница по доле символов) | дешёвые модели часто сваливаются на английский |
| вопрос длиннее `CASCADE_MAX_CHEAP_CHARS` | сложные задачи вообще не отдаём дешёвой модели — решается до вызова |

`score` — доля непройденных проверок, `accepted = score >= CASCADE_SCORE_THRESHOLD`.
Порог в конфиге, чтобы его можно было двигать, не пересобирая образ.

**v2 (не сейчас, но порт под это и сделан):** LLM-скорер на самой дешёвой модели с коротким
промптом «ответил ли текст на вопрос, 0–10». Включается флагом, когда появится бюджет.

## Домен

`RunTrace` получает три поля (миграция 005):

| Поле | Смысл |
|------|--------|
| `cascade_stage` | `off` \| `cheap` \| `escalated` — что произошло с этим ответом |
| `cheap_model_id` | какая модель отвечала первой (null, если каскад выключен) |
| `cheap_score` | вердикт скорера 0..1 (null, если скорер не вызывался) |

Попытка дешёвой модели пишется в тот же `attempts`-журнал обычной записью, так что
существующий Рейтинг видит её как любой другой вызов — отдельного учёта не нужно.

## Конфигурация (имена; значения — никогда в репозиторий)

```
CASCADE_ENABLED=false            # выключен по умолчанию: меняет поведение чата
CASCADE_CHEAP_MODELS=            # csv; пусто = взять первую модель из LLM_MODEL_CHAIN
CASCADE_SCORE_THRESHOLD=0.75
CASCADE_MIN_ANSWER_CHARS=40
CASCADE_MAX_CHEAP_CHARS=1200     # вопрос длиннее — сразу на сильную модель
CASCADE_TIMEOUT_SECONDS=12       # дешёвый этап не имеет права стоить как весь ответ
```

Каскад не применяется, когда пользователь **явно пиннит модель** в композере: явный выбор
человека сильнее любой автоматики (то же правило, что и для penalty из P2).

## API

Ничего нового. Расширяются два существующих ответа:

```jsonc
// GET /api/v1/sessions/{id}/traces — у каждого трейса
{"cascade_stage": "escalated", "cheap_model_id": "fast-mini", "cheap_score": 0.5}

// GET /api/v1/lab/pareto — одна сводка по окну, не по моделям
{"cascade": {"total": 42, "cheap": 31, "escalated": 11, "escalation_rate": 0.26}}
```

`cascade` отсутствует (`null`), когда каскад выключен, — панель тогда ничего не рисует.

## UI

Минимум, который рассказывает историю:

1. **Бейдж в футере ответа** рядом с моделью: «эскалировали» с подсказкой
   «Дешёвая модель не справилась — ответила модель посильнее». Только при `escalated`.
   На cheap-пути ничего не добавляем: отсутствие бейджа и есть «обошлись дешёвой».
2. **Строка под таблицей Рейтинга:** «Эскалации: 11 из 42 (26%)». Одно число, одна мысль.

Никакой новой панели, вкладки или цвета. Строки микрокопии — в чеклист до кода.

## Тестирование

- Unit: скорер табличными тестами на каждый признак (отказ, обрыв, незакрытый код, язык)
- Unit: use case на FakeLLM — cheap принят → одна модель в трейсе, `cascade_stage=cheap`;
  cheap отвергнут → две модели, `escalated`, читатель видит только второй ответ
- Unit: пин модели отключает каскад
- Unit: таймаут дешёвого этапа → сразу сильная модель, чат не падает
- Integration: SSE-прогон пишет `cascade_stage` в БД
- FakeLLM в CI, ключей нет

## Риски и что с ними делать

| Риск | Смягчение |
|------|-----------|
| Двойная задержка, когда cheap отвергнут | `CASCADE_TIMEOUT_SECONDS` + `CASCADE_MAX_CHEAP_CHARS` |
| Пропал эффект печати на cheap-пути | дешёвая модель быстрая; не имитировать стрим |
| Эвристика ошибается и эскалирует всё | `escalation_rate` в Рейтинге — сразу видно; порог в конфиге |
| Эвристика ошибается и не эскалирует ничего | 👎 из P2 по дешёвой модели — второй контур наблюдения |
| Каскад ломает media-tools | tool-раунд идёт до каскада и не участвует в нём |
