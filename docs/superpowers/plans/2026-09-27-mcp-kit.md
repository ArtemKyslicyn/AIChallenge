# aichallenge-mcp-kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. This repo is **not** the AIChallenge monorepo.

**Goal:** A small private repo that runs local MCP servers behind one Streamable HTTP `/mcp` + Bearer, so a visitor can paste the tunnel URL into AIChallenge Настройки → Подключения.

**Architecture:** One FastMCP (or official MCP SDK) HTTP gateway. Profiles enable subsets of wrapped servers. AIChallenge never vendors these processes.

**Tech Stack:** Node and/or Python as required by upstream MCPs; Docker Compose optional; Cloudflare quick tunnel documented, not built-in.

**Spec:** `docs/superpowers/specs/2026-09-27-guest-mcp-design.md` §3 (in the AIChallenge repo)

## Global Constraints

- Never commit real tokens (`GITHUB_PERSONAL_ACCESS_TOKEN`, kit Bearer).
- Default bind `127.0.0.1` — only the tunnel is public.
- Sandbox filesystem to an explicit `KIT_WORKSPACE` directory.
- Do not implement AIChallenge UI here.

## Team lane

### Task 2: HTTP gateway (dev profile)

Wrap official filesystem + git as Streamable HTTP on `http://127.0.0.1:3100/mcp` with Bearer `KIT_SHARED_TOKEN`.

- [ ] **Step 1:** Smoke: `initialize` + `tools/list` with the token must return at least one filesystem or git tool
- [ ] **Step 2:** Without token → 401
- [ ] **Step 3:** Commit `feat: expose filesystem and git over Streamable HTTP`

Use `mcp>=1.13,<2` FastMCP 1.x Streamable HTTP (same pin as `apps/mcp` in AIChallenge). Do not upgrade to FastMCP 2.
