**Scope:** Current `Composer.tsx`, `Chat.tsx`, `MediaJobCard.tsx` (+ related CSS). Labels, `aria-pressed`, focus, keyboard, touch targets, live regions, media dock. Readonly — proposals only.

### Critical / High

None remaining in this pass for the three scoped files. Prior High items (MediaJobCard live churn, silent `rulesMissing`) are addressed.

### Medium

**1. Media tool failures stay polite-only**  
On `tool_result` with `status === "error"`, Chat sets `setStatus(…)` (polite live region) and a transient error `MediaJobState`, but the dock only renders `phase === "running"`, and `setError` is not called for media tool errors. SSE `error` events correctly use `role="alert"`.  
**WCAG:** 4.1.3 Status Messages; 3.3.1 Error Identification.

**Fix:** For media tool failure, also `setError(event.error || "…")` (existing alert), or announce once with `aria-live="assertive"` / a dedicated alert. Keep Chat status as the single source; do not put `aria-live` back on the card.

**2. Textarea focus indicator is easy to miss**  
`.composer textarea { outline: none }` defeats global `:focus-visible`. Focus feedback is only `.composer-shell:focus-within` (border + shadow). Any child in the shell (model select, mode chips, settings) lights the same ring, so keyboard users cannot tell the message field is focused.  
**WCAG:** 2.4.7 Focus Visible (2.4.13 AAA if aiming higher).

**Fix:** Restore textarea `:focus-visible` outline (or an inner ring on the form row), and/or stop clearing `.composer:focus-within` styles so the field row itself differentiates. Optional: `aria-describedby` → keyboard hint (`Enter` / `Shift+Enter`).

**3. Sticky composer / media dock vs focus not obscured**  
Sticky `.composer-wrap` (z-index 50) + `.media-job-dock` sit over the thread bottom. `.thread-inner` pads for float-dock height, not for media dock + growing `--composer-h`. Tabbing to in-thread controls (feedback, lab expand) can land under the composer.  
**WCAG:** 2.4.11 Focus Not Obscured (Minimum).

**Fix:** Extra bottom padding on the thread when the media dock is visible; on `focusin` of thread controls, `scrollIntoView` so the focused control clears `--composer-h` (+ dock).

**4. Touch targets under 24×24 (2.5.8)**  
| Control | Issue |
|---|---|
| `.mode-chip-stack` | `padding: 5px 10px`; narrow ≤720px row layout can sit near/under 24px height |
| `.composer-model-select` | `padding: 2px` — short hit area |
| `.composer-more-toggle` / small `.ghost-button` | light padding; often &lt; 24px |
| `.text-link` (`padding: 0`) | empty-more + stand links fail 24×24 CSS minimum |

Note: `.composer-media-btn` already has `min-height: 24px`; send/stop is 40×40.

**Fix:** `min-height` / `min-width: 24px` (prefer 44px on narrow touch); expand `.text-link` hit area with padding without changing underline much.

**5. Idle mode-chip contrast / kicker size**  
Unpressed non-default stacks use `opacity: 0.72` and kicker `color-mix(… text-muted 65%, transparent)` at **9px**. Readable for sighted power users, weak for low vision; border/text vs adjacent chrome may miss 3:1 for non-text UI (1.4.11). Accessible **name** is fine via `aria-label`.  
**WCAG:** 1.4.3 / 1.4.11 (visual), 2.4.6 already OK for names.

**Fix:** Bump kicker to ≥11px; raise idle opacity/color so unselected chrome ≥3:1 against adjacent surface; keep pressed state clearly distinct.

**6. Model `<select>` double naming**  
Wrapping `<label>` (visible «Модель») + `aria-label="Модель ответа"` can produce noisy SR names.  
**WCAG:** 1.3.1 / 4.1.2 (quality).

**Fix:** Prefer one: `htmlFor`/`id` on the visible label, drop redundant `aria-label` (or hide the visual span from AT and keep `aria-label`).

### Low (still worth fixing)

**7. Send disabled with no reason in accessible name**  
Length overflow uses `role="alert"` (good). Empty / busy leave submit disabled with only «Отправить сообщение». Optional `aria-describedby` for «пусто» / «идёт генерация».

**8. `aria-controls` targets unmounted when collapsed**  
Panels are conditional-render (`settingsOpen &&`, `emptyMoreOpen ?`). When closed, `aria-controls` points at a missing id. Prefer keep-mounted + `hidden` / `inert`, or omit `aria-controls` when closed.

**9. Mode group could be exclusive radios**  
`aria-pressed` + group is acceptable. Optional upgrade: `role="radiogroup"` + `role="radio"` + `aria-checked` for exclusive modes (clearer SR pattern).

**10. Thread `aria-busy` during history load**  
`role="status"` on the loading line is enough for 4.1.3; optional `aria-busy={loading}` on `.thread` for AT that expose busy regions.

**11. Keyboard hint not programmatically tied**  
Visible `Enter` / `Shift+Enter` hint is not referenced from the textarea. Low discoverability gain via `aria-describedby` (compose with rules warn id when both apply).

### What’s already in good shape

- Mode buttons: `aria-pressed`, rich `aria-label`s, `role="group"`.
- Media draft actions: descriptive `aria-label`s; group labeled «Медиа».
- Textarea: `aria-label="Сообщение"`; Enter send / Shift+Enter newline; IME `isComposing` guard.
- Icon send/stop: `aria-label`; decorative SVGs `aria-hidden`.
- Length overflow + Chat SSE/network errors: `role="alert"`.
- Compare custom-rules gap: alert + `aria-invalid` / `aria-describedby`.
- Chat polite status live region covers generation, lab, temp studio, media lifecycle strings.
- MediaJobCard: visual status only; `aria-busy` while running; timer excluded from AT.
- Loading history: `role="status"`.
- Expand/collapse: `aria-expanded` + `aria-controls` on settings and empty-more.
- Temp studio bar: `role="group"` + RU field labels.
- Global `prefers-reduced-motion` near end of `index.css` clamps animations (including media spinner).
- Send control 40×40 (above 24px minimum).

### Suggested fix order

1. Assertive / `setError` path for media tool failures (Medium #1).  
2. Distinct textarea `:focus-visible` (Medium #2).  
3. Thread padding / scroll-into-view vs sticky composer + media dock (Medium #3).  
4. Touch-target mins on mode chips, model select, text-links (Medium #4); idle chip contrast (Medium #5).  
5. Model label cleanup; optional radiogroup / `aria-describedby` hint / keep-mounted panels (Medium #6 + Low).
